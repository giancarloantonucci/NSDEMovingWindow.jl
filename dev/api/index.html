NSDEMovingWindow.LeapParameters — Type
LeapParameters <: AbstractAdaptiveMoWiParameters

AMoWi-2: adapt the window shift Δτ (leaping and hopping) with the window length τ fixed. On success the next shift grows, capped by the window length: Δτ ← min(δΔτ⁺ Δτ, τ), the overlap constraint that stops the algorithm outrunning the speed at which the time-parallel subroutine can carry information. On failure the shift shrinks by δΔτ⁻, floored at one chunk length τ/N as a termination guard, and the window is re-attempted at the reduced shift. The first window is exempt from restarts: the strategy leaves τ alone, so if window 1 cannot converge, no shift policy can save it. Pick τ with care.

Constructors

LeapParameters(; δΔτ⁻=0.25, δΔτ⁺=2.0, R=10)

0 < δΔτ⁻ < 1, δΔτ⁺ ≥ 1, and R ≥ 0 are required. All factors must be finite.

NSDEMovingWindow.MoWi — Type
MoWi <: AbstractMovingWindowSolver

The moving-window algorithm: long-time integration through a sequence of overlapping windows, each solved by a time-parallel subroutine seeded from the previous window's solution over the overlap. The output is an ensemble of short window solutions, not one long trajectory: in chaotic systems each shift may jump orbit. See ensemblemean and friends for the statistics this enables.

The requested final time is a hard boundary: no window is integrated beyond it. A genuine final truncation is recorded in solution.clipped and excluded from ensemble statistics unless include_clipped=true. Gaps within the endpoint snap tolerance are treated as rounding and do not mark a window as clipped.

Constructors

MoWi(parallelsolver; adaptive=nothing, τ, Δτ=τ)

Arguments

  • parallelsolver :: AbstractTimeParallelSolver : copied for isolation; adaptive strategies replace settings in run-local state
  • adaptive : nothing for fixed windows, or one of StretchParameters (AMoWi-1), LeapParameters (AMoWi-2), ZoomParameters (AMoWi-3); the parameter type selects the strategy
  • τ :: Real : window length, τ > 0
  • Δτ :: Real : window shift, 0 < Δτ ≤ τ

NSDEMovingWindow.MoWiSolution — Type
MoWiSolution <: AbstractMovingWindowSolution

The output of MoWi: a vector of window solutions plus the restart count per window. clipped flags windows shortened by the global endpoint (tolerance-sized snaps are not marked). status is :not_started, :converged (all windows accepted or completed exactly), :budget_exhausted (at least one finite window used up its budget), or :nonfinite. A nonfinite run stops after its last retry and retains the failed window for inspection; ensemble statistics then raise ArgumentError. Read it as an ensemble of short-time solutions, not as one guaranteed continuous trajectory. Overlapping approximations can disagree; a shift need not change orbit when the solves agree. The statistics (ensemblemean, ensemblevariance, ensemblesem) compare equal relative positions across windows, which need not be independent.

NSDEMovingWindow.StretchParameters — Type
StretchParameters <: AbstractAdaptiveMoWiParameters

AMoWi-1: adapt the window length τ (stretching and shrinking). On a failed window the restart shrinks τ, Δτ and the coarse step by δτ⁻, with τ floored at N·h_F and Δτ at one chunk as termination guards; on success they grow by δτ⁺. The number of chunks N is fixed, so the coarse step scales with τ. The fine step stays fixed by default, since changing it can alter the resolved physics, unless fineupdate = true, which reproduces the idealised model used in the convergence analysis rather than the practical scheme. The fine step then scales with τ, so it stops shrinking when τ reaches its floor.

Constructors

StretchParameters(; δτ⁻=0.5, δτ⁺=1.25, R=10, fineupdate=false)

0 < δτ⁻ < 1, δτ⁺ ≥ 1, and R ≥ 0 are required. All factors must be finite.

NSDEMovingWindow.ZoomParameters — Type
ZoomParameters <: AbstractAdaptiveMoWiParameters

AMoWi-3: adapt the base weight w of the weighted proximity function with τ and Δτ fixed. The action is multiplicative and per restart: after ι restarts the weight is δ^ι w. A failed window loosens the measure (w ← δw⁻·w with δw⁻ > 1: a larger w makes the w^{-Δt} weights decay faster, so discontinuities further along the window count for less, "zooming out"); a success tightens it (w ← δw⁺·w with δw⁺ ≤ 1, clamped at w ≥ 1 in the stored configuration). Requires WeightedDefect(weight=FixedWeight(w)): changing weights within a window would overwrite the zoom adjustment. Use a probe run to measure a suitable base, then construct a fixed-weight criterion for Zoom.

Constructors

ZoomParameters(; δw⁻=2.0, δw⁺=0.25, R=10)

δw⁻ > 1, 0 < δw⁺ ≤ 1, and R ≥ 0 are required. All factors must be finite.

NSDEMovingWindow.ensemblemean — Function
ensemblemean(solution::MoWiSolution, g::Function=first; samples::Integer=100, include_clipped::Bool=false)

returns the ensemble mean of the functional g(u) across windows, sampled at samples equally spaced relative times over each window's own span, as a vector of length samples. g may return a number or a fixed-length numeric vector; vector-valued results are componentwise. Windows shortened at the global endpoint are excluded unless include_clipped=true. A tolerance-sized endpoint snap does not exclude a full window. Stretch windows still use their own relative time grids; these are comparisons at equal relative position, not equal elapsed time. solution.clipped records the endpoint truncations.

source
NSDEMovingWindow.ensemblesem — Function
ensemblesem(solution::MoWiSolution, g::Function=first; samples::Integer=100, include_clipped::Bool=false)

returns an independence-based estimate of the mean's standard error, using sample variance (divisor M-1) and at least two windows. Windows are seeded from earlier windows and may overlap, so this is not a correlation-adjusted uncertainty estimate. Positive correlations make it optimistic; it is not a guaranteed lower bound. Vector observables are handled componentwise. Endpoint-truncated windows are excluded unless include_clipped=true; M counts the retained windows.

source
NSDEMovingWindow.ensemblevariance — Function
ensemblevariance(solution::MoWiSolution, g::Function=first; samples::Integer=100, include_clipped::Bool=false)

returns the population variance across windows at equal relative times. For complex-valued observables this is the real mean squared modulus of the centred samples, componentwise for vector observables. Endpoint-truncated windows are excluded unless include_clipped=true, as in ensemblemean. This describes spread, not uncertainty of the mean.

NSDEMovingWindow.mowi! — Method
mowi!(cache, solution, problem, mowi; verbose=false, kwargs...)

runs the moving-window loop: re-target the shared window problem and parallel cache, seed the chunk starts from the previous window over the overlap (coarse elsewhere, through makeGs), solve the window with the time-parallel subroutine, then either accept and shift or restart under the adaptive policy. MPI runs collect and broadcast each window before the next seed is formed. The pipeline preserves the seeded window initial value but replaces interior overlap guesses during its coarse start-up; bulk backends use those guesses. nocollect=true is refused: the driver needs full window trajectories. Extra kwargs (e.g. history) go straight to the subroutine.

source
NSDETimeParallel.flatten — Method
flatten(solution::MoWiSolution)

concatenates every window's flattened trajectory into one (u, t) pair. Windows overlap and their approximations may disagree: t is non-monotone at window seams, and overlap regions appear once per covering window. Repeated overlap samples change sampling weights; concatenation alone does not justify attractor statistics or a single continuous trajectory. For relative-time ensemble summaries, use ensemblemean and friends.
